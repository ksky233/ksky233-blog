# ksky233 Blog｜UI 风格规范

## 1. 风格决定

博客采用“安静质感”作为唯一 UI 基准。

- [桌面预览](design/assets/安静质感-桌面预览.png)
- [移动预览](design/assets/安静质感-移动预览.png)


## 2. 核心气质

```text
安静
低饱和
温暖米白
大留白
轻玻璃质感
衬线标题
克制动效
适合长文阅读
```

避免：

- 高饱和科技蓝；
- 霓虹、赛博朋克与发光边框；
- 过密的信息面板；
- 大量渐变色块；
- 强烈弹跳和持续动画；
- 为了“技术感”牺牲正文阅读体验。

## 3. 基础颜色 Token

沿用参考模板的主色体系：

| Token | 浅色模式 | 用途 |
|---|---|---|
| `--bg-body` | `#f6f4f0` | 页面米白背景 |
| `--bg-card` | `rgba(255, 255, 255, 0.72)` | 半透明暖白卡片 |
| `--bg-card-hover` | `rgba(255, 255, 255, 0.90)` | 卡片悬浮 |
| `--text-primary` | `#1e1e2a` | 标题、正文主色 |
| `--text-secondary` | `#4a4a5a` | 摘要、说明文字 |
| `--text-muted` | `#7a7a8a` | 日期、标签、次要元数据 |
| `--accent-1` | `#c47b6b` | 陶土红主强调 |
| `--accent-2` | `#d4a08a` | 柔和珊瑚色 |
| `--border-light` | `rgba(0, 0, 0, 0.06)` | 轻边框与分隔线 |

允许在文章配图内部使用低饱和语义色：

| 语义 | 颜色 |
|---|---|
| 架构 A / Code-defined | 灰蓝 `#526A7B` |
| 架构 B / Workspace-defined | 墨绿 `#405B51` |
| 第三语义 / 共同结论 | 酒红 `#76555B` |

这些颜色用于文章图，不扩展为站点主导航和按钮的多色系统。站点 UI 的主要强调色仍是陶土红。

## 4. 字体

### 拉丁字符

- 标题：`Playfair Display`
- 正文：`Inter`

### 中文补充

参考模板没有显式中文衬线字体，Astro 实现时补充：

```css
--font-serif:
  "Playfair Display",
  "Noto Serif SC",
  "Songti SC",
  STSong,
  serif;

--font-sans:
  Inter,
  "Noto Sans SC",
  "PingFang SC",
  "Microsoft YaHei",
  system-ui,
  sans-serif;
```

正文默认使用无衬线字体；Logo、Hero 和文章标题使用衬线字体。代码使用系统等宽字体。

## 5. 圆角、阴影与动效

```css
--radius-lg: 28px;
--radius-md: 18px;
--radius-sm: 10px;

--shadow-soft: 0 12px 40px -12px rgba(0, 0, 0, 0.10);
--shadow-hover: 0 24px 60px -16px rgba(0, 0, 0, 0.18);

--transition: 0.35s cubic-bezier(0.25, 0.46, 0.45, 0.94);
```

卡片悬浮最多上移 `4px`。尊重 `prefers-reduced-motion`，减少不必要动画。

## 6. 页面结构

### 首页

```text
Header
├── ksky233 / Blog
├── 首页
├── 文章
├── 系列
├── 关于
└── RSS

Hero
├── 博客定位
├── 一句话介绍
└── 文章数 / 系列数

Main
├── Featured Article
├── Latest Articles
└── Sidebar
    ├── 关于作者
    ├── 系列导航
    └── 标签

Footer
```

首版文章较少时，不显示“热门文章”“评论数”和虚假的统计数据。侧边栏优先展示系列导航与标签。

### 文章页

- 正文阅读宽度控制在 `760–820px`；
- 标题区显示摘要、发布日期、原始笔记日期、复核日期、阅读时间和标签；
- 架构图允许突破正文宽度，但不能超过页面容器；
- 参考资料与系列导航放在文章末尾；
- 上一篇 / 下一篇按 `seriesOrder` 排列；
- 不在正文旁维持拥挤的常驻侧边栏。

### 历史技术文章

当 `contentStatus` 为 `historical` 或 `outdated` 时，在正文前显示提示卡：

```text
历史技术记录
本文整理自 YYYY 年的笔记，部分 API 已发生变化。
最后复核：YYYY-MM-DD
```

提示卡使用陶土红浅底和左侧强调线，不使用高风险警告红。

## 7. 技术正文样式

必须专门实现：

- `h2`、`h3` 层级与锚点；
- 行内代码与代码块；
- 表格横向滚动；
- 引用块；
- Note / Historical / Warning 提示卡；
- 图片、图注和可点击原图；
- 有序和无序列表；
- 外部链接标识；
- 脚注或参考资料；
- 中英文混排和长英文标识换行。

建议正文：

```css
font-size: 17px;
line-height: 1.85;
overflow-wrap: anywhere;
```

代码块和表格必须放在可横向滚动容器内，不能撑破移动端页面。

## 8. 响应式要求

断点：

```text
> 900px：文章列表 + 侧边栏
<= 900px：单列，侧边栏移到正文之后
<= 600px：收紧页面边距、卡片内距和标题字号
```

验收标准：

- `390px` 宽度无页面级横向滚动；
- 导航可以换行或收进菜单；
- 中文标题正常换行；
- 标签和元数据可以多行布局；
- 图片宽度不超过容器；
- 表格、代码块只在自身区域横向滚动；
- 点击目标不小于约 `40px`；
- 暗色模式保持足够对比度。

参考模板的当前移动预览存在内容横向裁切，只作为风格参考，不能直接视为移动端验收结果。

## 9. 外部资源策略

参考模板使用：

- Google Fonts；
- Font Awesome CDN；
- 外部示例头像。

正式实现规则：

- 不保留示例头像；
- 图标优先使用内联 SVG 或少量字符符号；
- Google Fonts 可以在首版使用，但必须提供系统字体 fallback；
- 不因字体或图标 CDN 加载失败破坏布局；
- 文章图片进入站点自身的 `public/images/` 或 Astro Assets。

## 11. 暗色模式

保留模板的 `prefers-color-scheme: dark` 自动暗色方案，但首版以浅色模式为视觉基准。

暗色模式需要单独检查：

- 正文对比度；
- 代码块背景；
- 半透明卡片边缘；
- 陶土红链接可读性；
- PNG 架构图在深色背景上的边界。

## 12. 实施约束

后续 Astro 组件不得自行发明另一套视觉语言。新增组件优先复用这里定义的：

```text
Color Tokens
Typography
Radius
Shadow
Spacing
Card
Metadata
Tag
Notice
Prose
```

如果确实需要修改核心 Token，应先更新本文，再修改站点代码。
